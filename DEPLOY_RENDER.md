# Deploy the upgraded Smart DIT Learning Hub on Render

This guide updates an existing Render + Supabase deployment without deleting the learning resources or learner data already in use.

## Start from the ZIP file

1. Right-click `metro and ruth project - ready to run.zip` and select **Extract All**.
2. Open the extracted `metro and ruth project` folder. Do not run the application from inside the ZIP.
3. Double-click `START_HERE.bat`, choose **1** to configure `.env`, choose **2** to test, and choose **3** to start locally at `http://127.0.0.1:5080`.
4. Only continue with this deployment guide after the local test displays `PASS: 40 ... checks`.

## Before you start

1. Keep the previous working GitHub commit available as a rollback point.
2. In Supabase, take a database backup and make sure the private `resources` storage bucket still exists.
3. Never upload `.env`, Supabase keys, Gemini keys, or a local `data/` folder to GitHub. The included `.gitignore` protects them.

## 1. Put this update in GitHub

From the extracted project folder in PowerShell, review and publish only the source files:

```powershell
git status
git add .
git commit -m "Add multi-user accounts, HOD approval and personal learning spaces"
git push origin main
```

If `git status` lists `.env`, `data`, `uploads`, or a ZIP file, stop and check `.gitignore` before committing. Secrets must never enter the repository.

## 2. Add the production environment variable in Render

Open **Render Dashboard -> your Smart DIT web service -> Environment**. Keep all existing values and add this new value:

| Key | What to enter |
| --- | --- |
| `HOD_ACTIVATION_CODE` | A unique private secret of at least 16 characters. It is used only to create the first Head of Department account. |

Also confirm these existing values are present and correct:

| Key | Required value |
| --- | --- |
| `APP_ENV` | `production` |
| `DATABASE_URL` | Supabase **Session Pooler** PostgreSQL connection string |
| `SUPABASE_URL` | Supabase Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase Secret Key (or legacy `service_role` key), server-side only |
| `SUPABASE_STORAGE_BUCKET` | `resources` |
| `SECRET_KEY` | A long secret generated by Render or your password manager |
| `INITIAL_STUDENT_PASSWORD` | At least 12 characters |
| `INITIAL_LECTURER_PASSWORD` | At least 12 characters |
| `GEMINI_API_KEY` | Your Google AI Studio Gemini key, if AI answers are enabled |
| `GEMINI_ENABLE_WEB_GROUNDING` | `1` for supplementary web sources, or `0` for lecturer-resource-only AI answers |

Do not put any of those secret values in client-side JavaScript, public screenshots, GitHub, or an ordinary Supabase browser key.

## 3. Deploy and watch the log

1. In Render, choose **Manual Deploy -> Deploy latest commit**, or wait for the connected GitHub branch to deploy automatically.
2. Open the **Logs** tab. A successful deployment reaches a healthy service and `GET /health` returns `200`.
3. The application creates only missing tables and columns at startup. It does not reset the existing database. The upload compatibility migration also removes the obsolete `is_demo_content` column that previously caused lecturer upload failures.
4. If Render reports `Missing production configuration: HOD_ACTIVATION_CODE`, return to **Environment**, add the value above, save it, and deploy again.

## 4. Activate the department workflow once

1. Open your public Render URL and select **Create account**.
2. To create the Electrical Engineering Head of Department, use an unused 8-10 digit numeric ID beginning with `5000` (for example `50001234`). Enter the private `HOD_ACTIVATION_CODE` when the protected field appears.
3. Sign in through the standard **Sign in** page using that ID/email and password. The account opens the Department workspace automatically.
4. A lecturer registers with an 8-10 digit numeric ID beginning with `1403`. Their account remains pending.
5. The Head of Department opens **Lecturer requests**, chooses the lecturer's permitted modules, and approves the request.
6. A student registers with an 8-10 digit numeric ID beginning with `2403`, chooses their programme, NTA level, and semester, then signs in. The dashboard, profile, AI chat and progress data are private to that student.

The HOD activation code is not a normal login credential. Keep it private; after the first HOD account exists, the application prevents a second Head of Department account for Electrical Engineering.

## 5. Test the public release

Use two separate private/incognito browser windows so the sessions cannot mix:

1. Register a test student and confirm the correct private student dashboard appears after sign-in.
2. Register a test lecturer; confirm they receive the pending-approval message and cannot open the lecturer workspace yet.
3. Sign in as the HOD; approve that lecturer with at least one module.
4. Sign in as the approved lecturer and upload a small TXT or PDF resource. Confirm it appears after verification.
5. Ask the AI about a resource, then sign in as a different student. The second student must not see the first student's conversation history.
6. Open the public site at a phone width and enable **Data saver** in Profile. Navigation should collapse into the menu and reduce visual effects.
7. Visit `https://YOUR-RENDER-URL/health`; it should return `{"status":"ok"}`.

## If something fails

| Symptom | Check |
| --- | --- |
| Build fails | Ensure Render runs `pip install -r requirements.txt` and starts `gunicorn --workers 1 --threads 4 --bind 0.0.0.0:$PORT wsgi:app`. |
| Service exits immediately | Read the first `RuntimeError` in Render logs. Add the missing environment variable exactly as named. |
| Database or uploads fail | Recheck the Session Pooler `DATABASE_URL`, Supabase URL, service-side Secret Key, and private `resources` bucket name. |
| Lecturer upload fails | Confirm the latest commit deployed; its startup migration removes the obsolete legacy upload column. Then inspect the Render log around the upload time. |
| AI says it is unavailable | Verify the server-side `GEMINI_API_KEY`, redeploy after saving it, and test ordinary chat with `GEMINI_ENABLE_WEB_GROUNDING=0` first. |
| A user sees the wrong workspace | Confirm the registration number starts with the intended prefix and the account status is active. Lecturer accounts need HOD approval. |

For a safe rollback, use Render's deploy history to redeploy the earlier known-good GitHub commit. Do not delete the Supabase project or storage bucket while diagnosing a deployment.
